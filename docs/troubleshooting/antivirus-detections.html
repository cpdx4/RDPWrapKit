Security tools flag RDPWrapKit

Some security tools and online scanners warn about RDPWrapKit. That can look alarming, so this page explains what the installer actually does, why each step is needed, and how each step is kept in check.

Why scanners flag it

Security tools judge what a program does, not why it does it

What you might see: a warning or a low trust rating from a security tool.

What it means: the tool noticed that the installer stops a Windows service and changes a Remote Desktop setting, so it treats it with suspicion.

To add remote-desktop support, an installer has to change how Remote Desktop is configured on the machine and restart the service that uses that configuration. Malware does some of the same things, so scanners treat the actions themselves as a warning sign. They cannot tell whether a program is doing it to help you or to hurt you.

RDPWrapKit is an RDP wrapper, and tools in that category are often labelled as hack tools or riskware by the companies that make the scanners. That label describes the category of the tool, not something harmful inside the file.

What it does, and why

Every step below is required for the product to work, and each one is kept narrow

  1. 01

    Changing one Remote Desktop setting

    We change a single Windows setting that tells Remote Desktop to load the TermWrap component. That setting is the on switch, so nothing works unless it is changed.

    We only change the values Remote Desktop needs, and we skip any value that is already correct.

  2. 02

    Stopping and starting Remote Desktop

    We need to modify how Remote Desktop works so it can run on your edition of Windows. To do that we stop the service, hook TermWrap in, and start the service again. Windows only picks up the change when the service starts, so the restart is the part that makes it work.

    It happens once, and Remote Desktop is left running and set to start automatically when Windows boots.

  3. 03

    Closing a small helper service first

    Remote Desktop has a helper service that depends on it. Windows will not stop Remote Desktop while that helper is still running, so we close the helper first.

    Only that one helper, and only while the restart is happening.

  4. 04

    Creating a local account, only if you ask

    The optional shortcut feature needs a Windows account to sign in with, so the installer creates one and gives it permission to connect. On Windows Home, the Administrators group is the only thing that grants that permission.

    This only runs when you turn the feature on, the name and password are yours to choose, and an account that fails to finish is disabled so it cannot be signed into.

  5. 05

    Using PowerShell for the account step

    Windows has no dependable built-in way for an installer to create a local account, so that one step uses a short PowerShell script.

    It is used for accounts only, and only after you open the account page. Service control, downloads, checks and cleanup all happen without it.

  6. 06

    Downloading two Microsoft files

    TermWrap needs the Microsoft Visual C++ runtime, and the shortcut is no use if the machine has no Remote Desktop client, so the installer fetches both from Microsoft.

    The addresses are Microsoft's own, the file size is checked, and a download is never run unless it carries a valid Microsoft signature. If a download fails you can install the file yourself.

  7. 07

    Signing the shortcut and storing the password safely

    Windows shows a warning on any unsigned Remote Desktop shortcut, and the client will only accept a saved password in protected form. So the shortcut is signed, and the password is locked to your own Windows login.

    Only the shortcut the toolkit just created is signed, with a certificate made on your PC and trusted for nothing else. The readable password is deleted as soon as the protected one exists.

  8. 08

    Ending a helper that stops responding

    If a helper hangs, setup would wait forever with Remote Desktop half-restarted, so the installer can end the process it started.

    Only our own processes, and only after a long wait.

  9. 09

    Turning off an old autoupdate task

    An older RDP Wrapper autoupdate task downloads and replaces the same files, which would undo what the installer just set up. When one is found, the installer asks before anything changes.

    One task, only with your permission.

  10. 10

    Checking that Remote Desktop is listening

    So the RDP Info page can tell you whether Remote Desktop is actually accepting connections, the installer looks at whether the RDP port is open on your own machine.

    Local only, and only the RDP port.

What it does not do

The short list that matters more than a scan result

  • It does not turn Remote Desktop off or leave it disabled.
  • It does not add itself to startup, to scheduled tasks, or to any service other than the Remote Desktop hook.
  • It does not open firewall ports or listen on the network by itself.
  • It does not download anything that is not from Microsoft, and it will not run a download that Microsoft did not sign.
  • It does not keep your password in readable form.
  • It does not switch off Defender, your antivirus, or Windows logging.
  • It does not contact any server of its own. There is no telemetry and no licence check.

If a scan worries you

Three quick checks you can do yourself

  1. 01

    Check that the installer is signed

    Right-click the setup file, choose Properties, and open the Digital Signatures tab. It should list a signature and say it is valid.

    If a file is edited by anyone, that signature stops being valid, so this is the quickest way to tell a real release from a modified copy.

  2. 02

    Make sure it came from the official releases page

    Download RDPWrapKit from the project's GitHub releases page, where the signed build is published.

  3. 03

    Look at what the installer did

    The installer writes a line into its log for each of the steps on this page, including the reason for it. If a scan worries you, the log is the plain record of what changed on your PC.

    You can find it in your temporary folder, in a file named RDPWrapKit_install_*.log, and read it in Notepad.

If a vendor still reports the file, you can report it as a false positive and mention which step on this page it flagged. Some will reclassify it; some will not, because extending Remote Desktop is what the tool is built to do. Either way, the checks above tell you whether the file in front of you is the one we published.
